# ServiceMonitor

Консольное приложение для проверки доступности интернет-сервисов и мониторинга собственных сайтов.

## Назначение

Быстро проверять, какие сервисы доступны, а какие заблокированы или лежат: не по новостям, а по факту пинга. Дополнительно позволяет мониторить собственные сайты.

## Целевая аудитория

- Пользователи, которым нужно знать доступность сервисов (YouTube, Discord, Telegram и др.)
- Веб-мастера, которым нужен мониторинг собственных сайтов
- Разработчики, которым нужна быстрая проверка инфраструктуры

## Предметная область

Мониторинг доступности веб-сервисов: проверка HTTP-статусов, отображение результатов, управление списком отслеживаемых сервисов.

## Основные сущности

- **Группа** (Group): название, описание, список входящих сервисов
- **Сервис** (Service): название, URL-адрес для проверки, описание,
  ссылка на группу
- **Результат проверки** (CheckResult): результат одного пинга сервиса —
  статус, код HTTP-ответа, время проверки, ссылка на сервис
- **Мониторинг** (Monitor): система, которая хранит группы и сервисы,
  выполняет проверки и поддерживает связи между сущностями

## Основные функции

1. Проверка доступности всех сервисов
2. Проверка отдельного сервиса по выбору
3. Отображение списка сервисов (с сортировкой по названию)
4. Отображение групп и их сервисов
5. Поиск сервиса по подстроке названия
6. Добавление нового сервиса (с указанием группы)
7. Удаление сервиса

## Реляционная модель

Сущности связаны между собой как таблицы в базе данных:

```
Monitor ─── содержит ───> Group ─── 1:N ───> Service ─── 1:N ───> CheckResult
                              ^                  │                     │
                              └──── N:1 (группа) ─┘                     │
                              └──────────── N:1 (сервис) ───────────────┘
```

- **Group → Service (1:N)**: в группе хранится список её сервисов
  (`group.services`), каждый сервис знает свою группу (`service.group`).
- **Service → CheckResult (1:N)**: у сервиса накапливается история
  проверок (`service.checks`), каждый результат ссылается на свой сервис
  (`result.service`).
- **Monitor**: владеет коллекциями групп и сервисов, при добавлении
  и удалении сервиса поддерживает обе стороны связей
  (`add_service()`, `remove_service()`), при запуске восстанавливает
  связи из загруженных данных.

Функции в `checker.py` — запросы над коллекциями (поиск, сортировка,
сбор и подсчёт результатов): они не изменяют объекты и не дублируют
логику `Monitor`.

## Объектная модель

- **Service** — проверяет сам себя (`check()` сохраняет `CheckResult`
  в историю), атрибуты результата проверки закрыты (`_available`,
  `_code`) и доступны через свойство `available` (инкапсуляция);
  `to_dict()`/`from_dict()` связывают объект с JSON.
- **CheckResult** — неизменяемая запись результата одного пинга:
  сервис, доступность, код, время.
- **Group** — владеет списком сервисов, знает, сколько их.
- **Monitor** — точка входа в структуру: проверки, добавление,
  удаление, поиск групп.
